# 诊断与恢复

## 只读晨检

运行 `python3 scripts/manage.py doctor --target '实际部署目录'`，并只读查看该目录 `state/monitor.log` 和 `launchctl print gui/$(id -u)/local.court-sms-automation`。

- 每分钟短任务的 `not running` 通常只是间歇状态；结合运行次数、退出码和扫描时间。
- 范围内最新入站编号与 last_rowid比较；编号差不是遗漏条数。
- message_jobs 的 done 仅表示该函数执行完毕，日历、提醒仍有独立队列。
- 检查 pending/retry/manual 任务及 pending_reports、pending_summons、manual_review。
- 检查 last_report_success_at 和 report_receipts。旧错误被后续成功恢复时不要误报持续故障。
- 文件按“周/案号/送达哈希/文书哈希/原文件名”保存；每次送达的 `.delivery_manifest.json` 记录实际内容校验值。不同送达的同名文件应并存。
- recovery_warning 表示发生过状态副本恢复，不能忽略。两个状态副本都不可用时后台停止，不会从零重扫。
- 手机有短信但 Mac 没有：先核对系统同步。不得重置短信库或修改手机账号设置。

只读检查报告区分已确认、待核和不支持。仅有进程运行或提醒存在，不能写“所有材料已下载”。

## 范围补查

先预览（不会变更状态、下载、写日历或提醒）：

```sh
python3 scripts/manage.py backfill --since YYYY-MM-DD --until YYYY-MM-DD
```

范围不得早于 config.start_date。用户授权该范围后添加 `--apply` 登记到持久任务队列；后续后台执行，并按短信编号更新提醒。补查不清零扫描游标，不改变日期范围，不把旧状态复制到新机器。执行时拿不到独占锁表示后台正在运行，稍后再试，不强杀进程。

## 状态恢复与停用

主状态和上一份有效状态分别为 `state/state.json`、`state/state.previous.json`。状态读写会验证结构；恢复副本有效时允许重放上一批任务，去重和文件校验应保证安全；两份均失败时安全停止。

遇到状态损坏：先停止服务、备份现存文件、审查恢复副本及材料清单。不得运行prepare、手写零游标或删除状态“修复”。仍无可靠恢复依据时让用户决定明确日期范围，重新建立可审查的补查计划。

```sh
python3 scripts/manage.py stop
```

该命令停止指定部署的服务，将 LaunchAgent 配置改为 `.disabled`；保留材料、源码、状态和日志。重新启用使用activate，不删除用户数据。

## 升级与回滚

本版本没有无人值守升级功能。先备份运行目录、配置、状态，停止后台；在隔离目录准备新版并测试，逐项比对配置和状态结构。不要将新prepare生成的空状态覆盖到已有状态。上线后验证最近短信、文件哈希和提醒；失败则停用新版，恢复备份代码与兼容状态，再检查外部提醒/日历是否已经写入，不能盲目再次创建。

## 人工处理

最多6次失败后，短信或传票任务转人工；通知写入失败则保留队列并退避。无链接短信与不支持的平台产生人工提醒，提醒含接收时间和摘要。验证码不应复制到分享包；原短信和访问链接只在使用者本机范围处理。

新传票日期不同不等于旧日程已经撤销。此系统不判断法律效力、送达时间、程序期限或哪份传票优先。人工确认后再由使用者决定日程变更。
