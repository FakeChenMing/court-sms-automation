# 法院网站辅助核对

网站用于用户明确授权的排期补查和同案主体确认，是短信及原件之外的补充来源。后台下载、OCR 和日历登记不依赖网站辅助聊天。可按接收者需要设置每天当地时间 09:00 等检查时间，但这是可选示例：读取技能不会创建定时任务；只有明确要求创建时才使用自动化工具，先检查已有任务避免重复，并验证实际模型为 `gpt-6.1-sol` / `max`。

## 登录与范围

先读取实际安装的浏览器技能，按用户浏览器偏好复用有效登录。可从人民法院在线服务首页 `https://zxfw.court.gov.cn/zxfw/#/pages/pc/home/index` 检查登录状态；不要默认固定工作区、页面编号或登录永久有效，也不要退出仍有效的会话。

只读“日程”“我的案件”及必要详情，按授权下载原件。遇登录、扫码、验证码或人工确认，保留页面交接用户。查询授权不包含签收、交费、确认送达地址、申请阅卷、延期、提交材料或发送消息；这些操作需要具体授权。不得读取、输出或保存密码、Cookie、Token、验证码和带访问授权参数的链接。未打开详情不得声称已核查详情。

## 排期补查

1. 首页所选日期的“暂无数据”不能说明整个账号无排期。进入完整日程，等待加载，检查筛选及分页；记录实际覆盖日期、页码、数量和最早最晚时间，明确未遍历范围。
2. 覆盖范围由接收者配置，可将未来排期及最近若干日变更作为辅助策略。网页列表缺案号时，先在案件页查明完整编号才能关联，不凭同名、日期接近或尾号配对。
3. 记录可见案件名、完整案号、法院、开始/结束、地点、页面性质、查询时间及不含授权参数的页面地址；不采集隐藏会话数据。
4. 网站“开庭”等可能是通用标签，不能覆盖通知原件明确的“调查”“证据交换”等性质。冲突保留待核并列来源；网站缺失不等于取消，网页变化也不能单独授权删除或改期。
5. 新排期须取得支持日期和事项的原始 PDF，按全文/日期审查及权限规则登记；无原件先列“网页排期待取得 PDF”。不能附其他案件材料，也不能把自制网页打印件冒充法院原件。已有事项在原 UID 补齐。

## 主体核对

以完整案号查询正确案件类别。案件名称能支持页面出现的姓名，不当然证明原告、被告或上诉人等角色。回看同案原件、当事人详情和明确关系语句，区分多方、同名、曾用名及诉讼阶段。详情无法进入时记录限制，不按姓名排列猜角色，也不用现阶段名单倒改历史日程。

名单和来源核实后写入接收者本地台账；标题按分侧简称，完整名单和角色保留备注及审计。新信息更新已有相关标题须在授权范围内，并保留人工内容。

## 去重、附件与结果

网页发现或查询日不等于实际收到日或法律送达日。沿用同案同收到日合并、独立到期和提前 7 日提醒规则，与后台共用锁及去重机制；没有新事实不重复写入。

检查已有附件需覆盖指定日历实际法院事项和新旧台账并集，逐项匹配支持该案号、日期及活动的原始 PDF。备注路径、附件标志和保存成功不代表附件完整。实际读取附件并比对内容 SHA；仅有远端地址尚未取得内容应标“内容待核”，不能直接判缺失。用户反映看不到时可检查日历详情显示，并将本机可见、云端登记、另一设备实际接收分别报告。

每轮记录网页覆盖、排期变化候选、主体补齐、附件核验、实际日历新增/更新及待核原因。登录过期、未加载完成、分页不全、缺原件及模型不可用分别说明。正常无变化不通知；有变化、故障或需要用户操作时简要报告。网站可查询不证明后台 OCR 或期限审查已完成。
