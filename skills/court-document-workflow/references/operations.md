# 接收者环境配置与验收

本模块提供审查、分组、登记与回读的集成源码，不提供已完成部署的保证。代码中的默认路径、日历名和服务名是待适配项；不能先启用后台再补配置。根目录旧下载器与本增强模块不是两套可同时写入相同事项的独立服务，接入时应明确唯一写入者和共享锁。

## 启用前配置

1. 明确接收日期范围、历史补查及历史短信只读范围、允许修改的日历和日程、旧项删除或合并权限、原件目录、状态目录、日志目录及成果目录。保留这些选择的配置记录；没有任何发布者的历史时间范围或操作授权随代码转移。
2. 检查 Python、Node、macOS Calendar/EventKit、实际使用的 OCR 服务及必要系统权限。模块根 `requirements.txt` 是直接 Python 依赖的唯一清单，`runtime-requirements.txt` 仅引用它；清单不包含全部 OCR 引擎、技能、法律服务、浏览器、模型登录或原生应用依赖。
3. 按实际目录接入下载器的逐次送达清单、工作队列及完成唤醒。检查下载游标、首次收到关联和去重状态；不要用清空旧状态解决兼容问题。服务标签由接收者选择，避免与已有任务冲突。
4. 安装并实际加载所需 OCR 和法律技能；配置可用法律 MCP 连接和白名单。公开包不含这些服务的账号或凭据。缺依赖时保留待办并明确报告，不声称已经调用。
5. 编译、签名并配置 Calendar 附件助手应用，接入 `run_attachment_helper` 的正常应用入口及独立输出文件；在接收者环境取得所需权限。不能直接使用发布者的签名身份、缓存或事件标识。
6. 配置官方 Codex CLI 可执行文件和现有有效登录，不提取、复制或输出认证令牌。配置 `gpt-6.1-sol` / `max`，并验证全文审查、独立复核和探针的实际请求参数。原生桥的 CLI 版本锁变化须重新做隔离测试；不能伪造版本或自动放宽配置。
7. 用虚构材料先验证非写入流程，再用接收者明确选择的样本验证真实日历全链路。通过后才启用后台；启用方式、运行身份、解释器、环境变量和唤醒方式均需适配。后台不要求 Codex 图形界面常开，但需要已登录的 macOS 会话、网络、模型登录、服务及权限；睡眠、离线时不保证即时处理。

当前源码的下载、入队、主体历史关联及收到节点检查仍有 2026-01-01 下限，下载器还有历史补查常量。这些是实现限制，不是接收者授权，也不是全部可通过环境变量改变的选项。部署前核对各入口与用户选定范围；需要更早年份时须一致修改相关代码、状态迁移及测试后再启用，不能只改提示词或本文说明。

### 已支持的环境变量

以下为当前源码实际提供的入口；路径应使用接收者自己的绝对路径。环境变量不替代系统授权、依赖安装、历史范围审查或真实样本验收。

| 变量 | 用途 |
| --- | --- |
| `COURT_STATE_DIR` | 状态、队列及回执目录 |
| `COURT_DOWNLOAD_ROOT` | 下载原件根目录 |
| `COURT_CALENDAR_NAME` | 目标日历；当前默认“法院工作日历” |
| `COURT_RUNTIME_DIR` | 运行代码目录；当前默认模块的 `scripts/runtime` |
| `COURT_WORKFLOW_LAUNCHD_LABEL` | 已配置的文书后台服务标签；未配置不唤醒 |
| `COURT_MODEL_NODE` | 模型桥所用 Node 可执行文件 |
| `COURT_CODEX_CLI` | 官方 Codex CLI；仍受源码中的已核验版本锁限制 |
| `COURT_CODEX_CONFIG` | 法律连接配置来源，不复制或输出其中凭据 |
| `COURT_LEGAL_MCP_NODE` | 法律 MCP 运输的绝对 Node 可执行路径 |
| `COURT_MINERU_BIN` / `COURT_PADDLE_BIN` | 已安装 OCR 引擎入口 |
| `COURT_OCR_BATCH_DIR` | 可选批 OCR 状态目录；未配置不读取旧批次目录 |

工作进程每次处理一轮后退出，支持 `--max-cases`、`--preview`、`--case`、`--probe-model`；不要添加不存在的 `--once`。`--preview` 仍须核对其实际行为及输入范围，不能仅凭名字推定所有外部服务均不调用。

## 模型与法律工具边界

`gpt_bridge.cjs` 使用官方 CLI 返回结构化审查结果或白名单法律查询请求，法律 MCP 调用由控制器执行。不得让模型自行访问电脑、浏览器、Calendar 或任意 MCP。进程级配置不修改用户全局权限或账号。

配置关闭本机工具执行通道及自动技能发现，使用临时会话、受控工作目录、只读模式、严格配置及输出结构校验。工具名称仍可能出现在请求中，不能宣称“模型完全看不到工具”。必须用无害临时文件 canary 实测强制工具调用会被拒绝，并确认文件未产生；桥检测到额外工具事件或运行期执行通道错误即拒绝该轮。只有精确识别的已核验启动提示可单独处理，不能忽略任意标准错误。模型自述和进程退出码不是隔离或模型身份的证据。

更换 CLI 版本、功能开关、模型、身份配置或依赖后重新验证。不得为消除“执行通道关闭”提示而启用工具通道。无论何种服务错误，不自动回退其他模型、不清空待办、不降低审查要求。HTTP 状态码需结合实际规范化原因判断，不能仅凭 402 推断具体账户余额。

认证、额度及配置错误按实现保存安全原因和重试时间；网络及限流短暂退避。避免记录服务任意原文、凭据或整个提示词。超时只清理本次所属进程，不结束其他应用。恢复后可用后台同一 Python 环境运行 `scripts/workflow_worker.py --probe-model` 做一次小型模型探针；探针不处理案卷、不写日历，也不能代替真实业务验收。

法律运输使用已配置的独立 Node。可用 `COURT_LEGAL_MCP_NODE` 指定绝对可执行路径；接入时检查当前源码默认值，缺失或无效应失败，不搜索不可信 PATH。法律 MCP 只开放必要检索、详情工具，实际调用留下可追溯回执。只发送规范检索关键词，不发送无关客户姓名或案号；不得将凭据写入技能、报告或公开仓库。

## OCR、审查与状态

先按原件 SHA-256 复用同目录 `OCR文本/<原件主名>.md`。逐页直接提取完整可靠的 PDF 文字层。其余页默认使用夸克 general-ocr，住宿发票用 vat-invoice-ocr，铁路电子客票用 general-ocr。本地 OCR 仅复核异常页。手写、签章和关键数字须对照原图，逐页记录原件指纹、实际引擎及复核状态。原件变化后更新，复核记录只适用于对应指纹和页码。 在运行入口的 Python 环境安装 `PyMuPDF==1.26.4` 和 `Pillow`。仅在允许将待识别页发送至夸克时配置 AI Agent 密钥，可设置环境变量 `SCAN_WEBSERVICE_KEY`，或在 `QUARK_OCR_DIR` 指定的私有目录中保存为 `agent-key`。日常和后台使用同一个缓存目录和账户。

按实际 OCR 技能监控系统内存：预计使用率达到 85% 时不启动新增 OCR，达到 90% 时停止本任务所属 OCR 工作进程；不终止其他任务。OCR 互斥等待及超时失败要保留待办，不以争抢资源为由结束别人的进程。

全文结果、独立复核、局部收到结果、OCR 质量及 Calendar 回读分别保留。独立复核发现遗漏时保留原候选和回执，补材料后有限轮次修正，每轮重新校验；未通过不登记。已有事项完成、撤回或被新文书解决的状态须纳入审查，不能把通用须知里的假设当成正在发生的任务。

## 同案同日收到组

程序用精确 `receipt_binding` 验证本件路径、SHA、清单和送达标识，从首次匹配的真实收到记录取日期。模型只提供 `receipt_materials`，不能填写收到日期或分组键。稳定组键为“完整案号|收到材料|YYYY-MM-DD”。不同到期和活动独立保留；同 SHA 重复通知不能重置日期。

`receipt_groups` 独立保存组决定、成员及回执。`receipt_documents` 逐项保留文书 id、SHA、路径、绑定、页码、原句、类型及核验依据；依据可以是真实材料页视觉记录、旧已验证收到回执或当前完整审查决定，不能把文字核验改称视觉核验。收到组决定是 `calendar_policy_version:4`、`receipt_only:true`、单条 receipt，不能标 `all_pages_reviewed:true`。

先记录各文书完整决定，再记录/写入收到组，最后处理各自到期或活动。中断先恢复待写组。后续批次必须保留旧组全部已核验成员、附件、到期和待核项；局部收到完成不改变成员全文状态。旧规则 ready 决定重新核验后才允许当前规则写入。

## Calendar、真实附件及恢复

由唯一写入者持有锁，对已有 UID 补齐，按完整案号、具体事项、对象和日期查重。标题、人工备注及既有提醒均保留；单纯标题修改不动日期、地点、备注、附件和提醒。批量核对覆盖实际日历及新旧台账并集。

附件和提醒助手经正常 macOS 应用入口启动，使用独立输出文件接收回执。`open` 成功只代表启动流程，不代表业务完成；必须核对 JSON、UID、事项标识、每份实际附件内容 SHA 及提醒。直接启动应用内部二进制可能处于不同权限上下文，不能用其失败结果替代正常入口验收；也不能自动修改隐私数据库或扩大系统权限。

文本写入后发生附件或提醒回读中断，保留 partial 和原 UID。恢复先以完整原方案调用只读 `review-inspect`；全部满足则补记真实回执，不先重写。附件不可读、确实缺失、提醒未核实、人工内容变化分别记录恢复错误并保留待核。不能以输入 PDF 的 SHA 冒充从 Calendar 附件读取的 SHA，不能只按同名文件判定完成。

附件的三层证据分别为：本机真实内容及 SHA、云端地址登记、另一台 Mac 实际接收。`extras_verified` 只表示本机附件及提醒核实；`uploaded` 或 `remote_url_registered` 不证明另一台 Mac 已收到。不保存远端附件访问地址，只保留必要布尔状态、时间及安全证据标识。

同步待核采用有限次只读重查，排除已归并旧别名；当前实现每轮至多 10 项、同项至少间隔 60 秒。成功更新同步状态，失败保留原因，不调用追加或替换。仅本机尚未缓存、暂时网络错误、远端地址缺失都不能直接据此删除或重复追加附件。

确需补齐或替换时，另行形成可审查的单项修复计划：核对准确 UID、最新元数据、完整附件清单、原件内容和具体授权，保留所有其他字段与附件。已存在远端地址但正常下载明确失败的例外还需保存原始错误证据；不能将一次案件修复扩大成日常自动替换。本公开包不包含具体用户的修复授权或固定对象命令。

## 健康检查与回退

只读检查 `document_review.json`、`model_service.json`、`workflow_health.json`、各轮 `result.json` 和必要安全日志。分别统计下载、OCR 完整/局部、全文完成/待核、收到组、确定到期及活动、日历写入/回读、本机附件、云端待核、失败保留。短任务不在运行状态不必然故障，退出码 0 不代表任务完成。

维护前备份代码和状态。回退先停止相应文书服务，保留下载、队列和已产生的回执；恢复代码后先查实际日历，不能用旧状态覆盖新回执或重建已写 UID。旧日程不自动删除；读取本技能也不会创建、替换或启用定时任务。

## 最小验收集

- 所有页都已读取；文字 PDF、图像 PDF、混合 PDF、空白页及局部 OCR 失败各有正确质量状态。
- 同案历史文书能补齐主体；短信问候不当成当事人；同尾号不同完整案号不串案。
- 明确排期保留原件具体性质；缺法律起算的期限不造截止日；已核实收到可独立登记。
- 同案同日多材料只建一个收到组；不同截止仍独立；重复通知和重跑不造新节点。
- 两节点日期备注、主体、真实 PDF 和提前 7 日提醒正确；人工内容及提醒保留。
- 写入中断后只读恢复原 UID；不可读附件阻断完成，不重复添加；本机、云端及另一设备状态分别报告。
- 实际 GPT 请求为 `gpt-6.1-sol` / `max`；越权工具尝试被拒绝；探针成功后仍需样本全链路验收。
- 法律 MCP 不可用、模型错误、原件缺失或冲突时保留待核，不能将队列为空或扫描追平作为通过依据。
