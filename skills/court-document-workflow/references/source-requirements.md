# 资料来源与核验要求

本文件约束审查如何取得证据，不预先替接收者案件作法律结论。实际起算、期限及适用规则应随当前材料和查询核验。

## 文书与收到记录

保存原件内容 SHA、页码、连续逐字原句、OCR 质量和实际核图记录。完整阅读不能由文件名、检索关键词或单页摘要替代。不同 OCR 结果并列保留；关键矛盾未解决时待核。

收到节点需要本件原文件路径、SHA、下载清单及对应送达通知的精确关联。归档周、文件修改时间、下载时间接近或同案编号不能单独证明收到日期。重复通知不自动重置第一次真实收到记录。

法律起算与事实上的收到分开。电子送达相关记录既不自动等同法律送达，也不一概排除；逐项核对适用规则、同意、送达系统和地址、到达或阅知记录、具体文书关联等必要条件。缺送达、生效、实施或其他起算事实时列出缺口，不算替代日期。

## 法律资料

实际读取匹配法律技能并调用已配置法律 MCP。法规、司法解释优先使用法规检索和详情工具；关键结论原则上由两个独立来源交叉核对。单一来源、调用失败或来源冲突必须写明，继续尝试适合的其他来源；不能将普通网页检索冒充法律 MCP 已调用。

逐项保存法规名称、机关、文号、条款、施行日期、当前及适用时点效力、具体条文、平台及工具回执、查询日期和交叉核验结论。引用现行条文前先验证适用版本。只检索影响本次办理的规则，通用须知里没有发生的假设不扩大成实体案件分析。

使用官方网页补充节假日或法源时保存支持该事实的页面来源和日期。法律请求仅带必要规范关键词，避免发送无关案件身份资料。原始回执保存在接收者私有审计，不公开凭据或访问授权链接。

## 日期计算

明确日历日期、经核验可计算的相对期限和待核事项分开。可计算事件须有真实起算证据、条款、算式、适用年度官方节假日和独立复算；程序复算不一致就拒绝写入。文书内部明确指向另一同案排期的，保留两份原句及 PDF，不把一般关联当成明确指向。

`holidays.json` 是附来源的公开数据快照，不是永久适用或所有年份的保证。使用前复核对应年度官方安排、调休及来源效力；缺失年份或来源有问题时不得自行补猜。节假日规则是否适用于该类事项也需核验，不能把所有活动、冻结届满或内部提前管理日期机械顺延。

保全、执行和轮候状态以具体材料为依据；届满与续保申请截止分别审查。到期提前 7 日只是提醒设置，不替代更早法定或法院要求的办理时点。

## 主体与最终结果

以完整案号关联材料，逐个姓名保存角色来源。收件人问候、被传唤人或网页案件名不能独立推定原被告。来源明确的“甲诉你”“你诉乙”可结合同页称谓核对；无角色时如实标记，不能凭排序补角色。阶段变化和来源冲突必须保留。

交付和状态统计列明实际审查覆盖、法律 MCP 调用及交叉核验、仍欠缺事实和 Calendar 回读范围。需要法律成果文件时附“资料来源与核验情况”，重要事实和观点就近标注来源。收到局部核对、本机附件、云端地址登记或模型探针均不得冒充更大范围验收通过。
